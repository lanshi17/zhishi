# 知食 ZhīShí v1.0.0

首个正式版。个人健康热量追踪助手：在微信里用自然语言记录每日饮食与运动，由 LightRAG 知识库提供热量数据，PostgreSQL 持久化，自动生成日/周/月/季/年热量报告。

First stable release of the WeChat calorie-tracking assistant: natural-language
diet/exercise logging, LightRAG knowledge lookups, PostgreSQL persistence, and
daily/weekly/monthly/quarterly/yearly calorie reports.

## 亮点 / Highlights

- **微信端交互**：iLink 网关 + 长轮询，QR 登录后即可收发消息（`bun run start:wechat`）。
- **5 阶段 agent 流水线**：意图分类与实体抽取（LLM）→ LightRAG 检索 → 结果合并 → 动作执行（PostgreSQL）→ 回复格式化。
- **知识库核算**：LightRAG（1024 维 `bge-m3` 嵌入，混合检索）返回食物/运动的热量依据，而非模型臆测。
- **确定性热量工具**：`health.calculate_intake` / `health.calculate_expenditure` 直接汇总已落库记录；消耗包含记录的运动与 BMR（需完整画像）。
- **强制工具调用**：健康流程在未调用注册工具前拒绝直接回复，避免无依据数值。
- **周期报告**：日/周/月/季/年聚合，含摄入、运动消耗、基础代谢与净热量。
- **对话上下文**：按用户持久化消息，`LLM_CONTEXT_WINDOW` 控制恢复预算（默认 256000）。
- **图片食物估算**：iLink 收到的图片交给 vision 模型，经 `health.record_diet` 落库。
- **审批与执行器**：工具调用审批引擎 + TUI 操作界面，支持审批恢复。
- **工程化**：Bun 1.4.2 工具链、`bun.lock` 冻结安装、246 个 Vitest 测试；GitHub Actions 门禁（typecheck / test（pgvector:pg18）/ build）与 tag 触发发布。

## 运行要求 / Requirements

- Bun `1.4.2`（仓库内 `.bun-version` 固定；应用依赖 Bun 自动加载 `.env`）
- PostgreSQL 18 + pgvector（开发库 `wechat_claw`，测试库 `wechat_claw_test`）
- OpenAI-compatible LLM 端点（`LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY`）
- 可选：LightRAG 服务（`LIGHTRAG_API_URL`）、Tavily 搜索（`TAVILY_API_KEY`）、iLink bot token（`ILINK_BOT_TOKEN`）

## 安装与启动 / Install and run

```bash
bun install
cp .env.example .env   # 填写 LLM、DATABASE_URL、ADMIN_USER_ID、WORKSPACE_ROOT 等
bun run start:wechat
```

数据库迁移在启动时自动执行；测试用 `bun run test`（需先创建 `wechat_claw_test`）。

## 制品 / Assets

- `zhishi-v1.0.0.tar.gz`：`bun run build` 产出的 `dist/` 编译结果，解包后配合 `.env` 运行。

## 已知限制 / Known limitations

- 仅支持单个可信管理员账号（`ADMIN_USER_ID`）。
- 依赖外部 LLM 与嵌入服务，离线不可用；LightRAG 与微信登录均为外部前置条件，未随制品打包。
- 版本纪律：发布 tag 必须与 `package.json` 版本一致（本版要求 `v1.0.0`，由发布工作流强制校验）。
